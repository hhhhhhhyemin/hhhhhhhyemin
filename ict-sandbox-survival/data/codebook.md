# 변수 정의 (Codebook)

`data/sandbox_projects.csv`에 과제 1건당 1행으로 입력합니다. 날짜는 `YYYY-MM-DD` 형식입니다.

| 변수 | 필수 | 설명 | 예시 |
|---|---|---|---|
| `project_id` | O | 과제 고유번호. 포털 번호가 있으면 그대로 사용 | `ICT-2019-001` |
| `project_name` | O | 과제명 | 모바일 운전면허 확인 서비스 |
| `company` |  | 신청 기업명. 공동신청이면 `;`로 구분 | |
| `designation_date` | O | 심의위원회 지정(승인)일. **생존시간의 시작점** | `2019-02-14` |
| `sandbox_type` | O | `실증특례` / `임시허가` / `적극행정` | `실증특례` |
| `field` |  | 서비스 분야 | `모빌리티`, `헬스케어`, `핀테크`, `공유경제` 등 |
| `ministry` |  | 규제 소관부처 | `국토교통부` |
| `company_size` |  | `대기업` / `중견기업` / `중소기업` / `스타트업` | |
| `law_amended_date` |  | 관련 법령 개정이 완료되어 특례 없이 사업이 가능해진 날. **사건(event) 발생일**. 미정비면 빈칸 | `2021-06-01` |
| `termination_date` |  | 법령 정비 전에 특례가 취소·포기·만료되어 사업이 중단된 날. **경쟁위험** 발생일. 해당 없으면 빈칸 | |
| `termination_reason` |  | 취소/포기/만료 등 사유 | `사업 포기` |
| `source_url` |  | 근거 자료(보도자료, 포털 페이지) 링크 | |

## 사건 정의

- 시작점: `designation_date`
- 사건(event = 1): `law_amended_date` — 관련 법령(법률·시행령·고시 등) 개정 완료
- 경쟁위험(event = 2): `termination_date` — 법령 정비 전 특례 종료·사업 중단
- 중도절단(event = 0): 관측 종료일(`config.R`의 `CUTOFF_DATE`)까지 위 두 사건이 모두 없음

`law_amended_date`의 기준(공포일 vs 시행일)은 연구 전체에서 하나로 통일하세요. 기본 권장은 **시행일**입니다.

## 수집처

- ICT 규제샌드박스 포털(과학기술정보통신부·NIPA): 지정과제 목록, 과제별 상세
- 규제샌드박스 통합포털(국무조정실): 법령 정비 현황
- 과학기술정보통신부 보도자료(심의위원회 개최 결과): 지정일, 과제명, 특례 유형
- 국가법령정보센터: 관련 법령 개정 공포일·시행일
